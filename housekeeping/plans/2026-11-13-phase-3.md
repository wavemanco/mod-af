# housekeeping Phase 3 plan (draft 2)

Phase 3 adds `owed`, `audit`, the automatic parts, the notes for `loose-ends`, `route` and `decide`, and the README
(DESIGN 3.9, 3.10, 3.11, sections 6 and 7; backlog rows HK-002 to HK-005).

It follows Google's Elephant-Goldfish model (EGM). The "Elephant" is the session that holds the project's context
and drafts; "Goldfish" are fresh reviewers that read the draft and the code with none of that context, each from
one "lens" (design, codebase, readiness, comprehension, structure, scope, invention). The steps so far:
- a brainstorm by seven lenses and a synthesis: `research/phase-3-concepts-brief.md`;
- draft 1 of this plan;
- a review of draft 1 by seven lenses: 6 Blockers, 29 Majors, 14 Nits (`research/phase-3-plan-review.md`). Draft 2
  answers every one, and takes the cuts the reviewers offered where a cut removes a risk instead of managing it.

The owner asked on 2026-11-13 (UTC) for no stop-and-ask in this phase: "deal with things autonomously". Every
question is settled below as Claude's call, with the options rejected and why, and DESIGN section 10 lists them
for the owner to check.

Terms: the **controller** is the session that runs the build and pushes; a **builder** is one agent doing one task;
**the kit** is `claude plugin test`, whose tests drive the hooks with fakes and no model; **the gate** is defined
under "How the build runs".

## Stop rules for the build

- No agent starts a live session, pushes, opens a PR or publishes.
- No change to `version: 1` in the settings, to the agent-guide line, to the "How this file is kept" heading, or to
  `prompts/survey.md` and `prompts/plan.md`.
- A builder that finds an item larger than its entry leaves the larger part undone, files a row, and goes on.
- A question this plan does not settle is the builder's to report, not to decide.

## How the build runs

- Branch `housekeeping/phase-3`, cut from main at b14fdcf (the Phase 2 merge). Five tasks in order, one builder each;
  they share `housekeeping/hooks/register.tsx`, so they never run at once.
- Each item has the named tests below, written to fail before the change. A test that cannot be written is a
  reason to stop that item, not to skip the test.
- The gate, run at the end of each task:
  - `claude plugin test housekeeping`;
  - `node --test housekeeping/node-tests/*.spec.ts` with TEMP and TMP set to a folder in the scratch directory;
  - `claude plugin validate housekeeping`;
  - the name and word searches over the branch's diff and commit messages, against the git-ignored lists in
    `housekeeping/research/raw/`, and the author and committer check (counted, never printed).
- The controller pushes after each task's gate passes (mod-af's root CLAUDE.md, 2026-11-10: "Commit and push each
  piece of work as soon as it is finished, before it is reviewed"). The narrow check runs over the whole branch
  after Task 5; its findings are filed, and the owner decides any fix round (stop rule 3) except for a secret,
  an address or a denied file reaching a page or the agent, which the controller fixes at once.
- Engine facts the plan relies on are read from the engine's types and pinned with kit fakes; a kit test proves the
  plugin against the fake, not against the engine. Every such fact is listed in `research/live-checks.md` for the
  owner's sitting.
- Kit fakes to add in `housekeeping/tests/plugin.test.ts`: `git diff --quiet` (exit 0 unless the world says the
  records changed), a `rev-list --count <a>..<b>` answered from the world, a stand-in for `prompts/audit.md`, a Bash
  and a PowerShell tool.call fake whose result carries `gitOperation`, and an Edit and Write tool.call fake.

### Task 2: `owed`

Files: Modify `hooks/core/history.ts`, `hooks/adapter.ts`, `cli.ts`, `hooks/register.tsx`, `FORMAT.md`,
`tests/plugin.test.ts`, `node-tests/cli.spec.ts`; Create `hooks/core/owed.ts`, `tests/owed.test.ts`.

- **The range.** The base is `git merge-base <main> HEAD`, or a given `--base <ref>` run through merge-base with the
  head; the head is HEAD or `--head <ref>`. The diff is `<base>...<head>`. `--end-of-options` comes before every
  ref. The log reads `<base>..<head>` without `--first-parent`, sha and subject only.
- **Reading, with no history walk.** The records at the base, the head and main's tip are read by the existing
  readers (`show`/`filesAt` on each route) with argument builders in `history.ts`; owed.ts stays pure over
  `snapshot()` and `idsIn`. Changed paths come first from `git diff --name-only`; then `git diff -U0` in batches of
  paths under about 30,000 characters of command line; binaries are left out. A path or a batch cut short is
  counted as not read, never a stop.
- **The code-name rule** (FORMAT, with these test cases): a token in a Trigger is a backticked span, or a word that
  holds `/` or ends in `.` and letters. A row fires when a token matches a changed path as a suffix on a `/`
  boundary, or a whole word on an added or removed line outside the two records and the settings file. Duty rows
  and slash commands are left out. FORMAT's line that backticks mean nothing is amended for Triggers.
- **What it lists**, grouped: rows whose Trigger fired, each with the token and the path and line number it
  matched; rows the commits name by ID, each with the commit's sha and subject; the checklist lines that name those
  rows; rows gone over the range (`historyFrom([snapshot(base), snapshot(head)])`: open at the base, absent at the
  head, in no Done table); rows already settled (moved to Done at the head), listed apart; IDs the branch adds that
  main's tip or the base already holds. Evidence never includes a line's text. The output is masked, and paths
  that a shell can read as commands are marked as the survey marks them.
- **Read rules.** On the plugin route every changed path, both sides of a rename included, is put to the Read rules
  with readTracked's allow rule (an ask with no rule outside the session's folder counts as denied); denied paths are
  excluded with `:(exclude)` pathspecs and counted, never named. When anything was excluded, no reply or context
  names the Node owed. README and FORMAT say that `node cli.ts owed` ignores the Read rules.
- **Commands.** `/housekeeping owed [--base <ref>] [--head <ref>]`; `node cli.ts owed [--base <ref>] [--head <ref>]
  [--repo <dir>] [--settings <file>]`. Exit 0 with a listing; exit 2 on a usage error, a stop or a git error.
  On main with nothing between base and head, the reply says to give a base.
- Tests: the default base; a given base; a denied path counted and its name and lines absent from the reply; a
  cut-short batch counted as not read; no local main; a shallow clone; each code-name case; a duty row not firing;
  a collision with main's tip; a settled row listed apart; a gone row; no line text in the evidence.

### Task 3: `audit`

Files: Create `prompts/audit.md`, `tests/fixtures/audit/` (a repository builder), `node-tests/audit.spec.ts`;
Modify `hooks/register.tsx`, `tests/plugin.test.ts`.

- **`prompts/audit.md`**, the procedure, with these rules written out:
  - **Where writing is restricted** (call 11): before anything, look for a rule on who writes the records; if one
    exists, list every case and write nothing.
  - **A dirty tree:** if `git status --porcelain` is not empty, apply nothing, list the cases and say why. Never
    stash, reset, `checkout --` or clean.
  - **An earlier audit branch:** if an unmerged `housekeeping/audit-*` branch exists, stop and name it.
  - **The range** (call 2): the duty row's latest Last done sha, validated with
    `git rev-parse --verify --end-of-options <sha>^{commit}` and checked to be an ancestor of main; else the
    settings commit; at most the last 50 first-parent commits, said in the reply.
  - **The evidence:** `owed --base <start> --head <main>`. Then, for at most 25 row-and-commit pairs, strongest
    first (a closing word, then the ID named in the subject, then in the body), read only the hunks owed allowed:
    `git show <sha> -- <allowed paths>`, never a whole commit, never `--stat`. Pairs past 25 are counted.
  - **Clear-cut** means all three: the commit's subject or body has a closing word ("close", "closes", "closed",
    "fix", "fixes", "fixed", "done", "land", "lands", "landed", "resolve", "resolves", "resolved", any case) next to
    the ID; the change the hunk shows is still present at main's tip (`git show <main>:<path>` holds it); and the
    skeptic agrees.
  - **The skeptic:** a fresh subagent that is not a fork, per batch of 10 proposals, given only each row's ID and
    Item, the claim, the sha and subject, and the allowed hunk. Only cases it agrees with are applied. With no
    subagent available, every case is a judgement call.
  - **Applying:** a branch `housekeeping/audit-YYYY-MM-DD` from main, made with `git worktree add` in a folder
    outside the person's checkout; one commit per change, each naming its proving sha; Done rows in the shape of the
    file's existing Done rows; checklist lines ticked whose rows are all closed. The duty row's Last done is updated
    "through <main's sha>", unless pairs were left past the cap, in which case it keeps its sha and the reply says
    to run again. With no duty row, the audit adds it as the one row it may open, word for word:
    `| <next ID> | Audit the records against the commits | none | agent | no: a standing duty | Every 2 weeks:
    /housekeeping audit | — | Last done: YYYY-MM-DD, through <sha> | YYYY-MM-DD |` (cells in the playbook's own
    column order). The branch is never pushed: it is the owner's to push and merge.
  - **The check after applying:** before and after, `node <home>/cli.ts map --settings <a copy whose mainBranch
    is the audit branch> --out <a scratch file>`, and compare the partition lines: closed up by N, open down by N.
    `owed --base main --head <audit branch>` lists no gone row. Any other result: delete the branch and report.
  - **Judgement calls** (partly done, done differently, gone rows, doors, "opened" work): listed in the reply with
    their evidence; on the branch, a row gets only "Audit YYYY-MM-DD: <claim>, left for the owner" appended to its
    Details cell with `<br>`.
- **`/housekeeping audit`** hands the procedure with owed's listing over the range (`handPrompt`). The time-out
  reply names `prompts/audit.md` and `node <home>/cli.ts owed --base <sha> --head <main>`, unless owed excluded a
  denied path.
- **The acceptance run** (DESIGN 7: at least 9 of 10 planted done rows found, no wrong change applied):
  `tests/fixtures/audit/` builds a repository with 10 rows closed by commits and 6 decoys (a revert, "prep for X",
  partial work, a passing mention, an ID only on a side branch, a closing word for another ID). After Task 3, the
  controller has a fresh subagent follow `prompts/audit.md` on a clone of it and scores the branch. The spec checks
  the fixture's shape; the score goes in the task's result.
- Tests: the procedure is handed with owed's listing; the time-out reply in both cases; the record holds audit's
  keep text; the fixture builds with its 16 cases.

### Task 4: the automatic parts

Files: Modify `hooks/register.tsx`, `.claude-plugin/plugin.json`, `tests/plugin.test.ts`.

- **`userConfig`** in `plugin.json`: `"automatic": { "type": "string", "title": "Automatic parts", "description":
  "on or off", "default": "on" }`, read from `register(on, options)`. Off stops what call 8 names.
- **Compaction** (main conversation only, every trigger; forks and other subagents unchanged): where
  `.housekeeping.json` exists, a paragraph asks the summary to keep, under the heading
  "Not yet filed into the backlog or playbook", one line per item not yet written into the two files in this
  conversation, the owner's decisions word for word, at most 40 lines, then "and N more: run /loose-ends". It is
  built apart from the procedure paragraph; a failure in either keeps the other; it fails open. The pinned tests
  that a compaction with no procedure sent "goes on as it came" change on purpose: with the settings file, the
  paragraph is added; without it, the event passes unchanged. DESIGN 3.8 and 3.10 change in the same commit.
- **After a commit, a merge or a pull, on the Bash and PowerShell tools.** The hook's shape:
  `const got = await next(e)` first, outside any try, before any early return; then, inside a try whose catch
  returns `got`: return `got` unless `automatic` is on, the result has a git operation or the command matches
  `\bgit\b`, the result carries no `backgroundTaskId`, and `.housekeeping.json` exists; if main's sha differs from
  the stored view's and `git diff --quiet <old> <new> -- :(literal)<backlog> :(literal)<playbook>` exits 1, start
  the rebuild without waiting, refresh the status line when it lands, and, on the main loop only, return
  `{ ...got, context: [...(got.context ?? []), line] }` with the masked line "The records on <main> changed at
  <sha7>; /housekeeping shows the new view." Registered with `.catch(($, e, next) => next(e))`.
- **Work and filing, on the Edit, Write and NotebookEdit tools:** a hook that only marks, in memory, that work was
  done, and that filing was done when the path is one of the two records files. The same `got`-first shape.
- **At the main loop's turn end** (`turn.complete` with no `agentId`, reason `answer`), when `automatic` is on:
  - suggest `/loose-ends` with `$.prompt.suggest({ text: '/loose-ends' })`, not awaited, at most once per HEAD sha,
    when `git rev-list --count <last commit touching the records on HEAD>..HEAD` is 3 or more and neither records
    file has uncommitted edits; the HEAD at the last suggestion is stored under the repository's key;
  - when work was marked after the last filing, write the catch-up record `catchup:<repository key>:<session id>`:
    the session's root folder, its id, counts and shas only, never item text.
- **At session end:** in one write, set the record's `ended` and the resume id from `e.resume`.
- **The catch-up offer:** on the first prompt.context for a session id this process has not seen, when `automatic`
  is on and the session started interactive (kept in memory from session.start), for each ended record of this
  repository other than this session: write once with `$.ui.log`, to the transcript, never to the agent: "A session
  that ended with work not filed can be resumed: in <root>, run claude --resume <id>, then /loose-ends." Then delete
  the record. Records older than 14 days are deleted with `$.store.keys()`.
- **The stale-map line:** at session start, when a Route Map link is stored and `git diff --quiet <its sha> <main>
  -- <records>` exits 1, one `$.ui.log` line: "The Route Map is older than the records on <main>: /housekeeping map
  publishes it." Skipped when no link is stored.
- **Debug lines** (call 16) from each of these.
- Tests: the shell hook runs the command once when it throws before or after `next`; no git call without `\bgit\b`
  or with `automatic` off; PowerShell; a merge (`branch.action: "merged"`); no rebuild when the records are
  unchanged; no line in a subagent; a background command skipped; the compaction paragraph only with the settings
  file and only in the main conversation; the procedure paragraph survives a throw in the new one; the suggestion
  once per HEAD and not with uncommitted records edits; the catch-up never offered for a record not ended, a run
  that was not interactive, or the same session; records of another repository never offered; the stale-map line
  only with a stored link.
