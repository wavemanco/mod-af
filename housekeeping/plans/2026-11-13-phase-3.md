# housekeeping Phase 3 plan (draft 3)

Phase 3 adds `owed`, `audit`, the automatic parts, the notes for `loose-ends`, `route` and `decide`, and the README
(DESIGN 3.9, 3.10, 3.11, sections 6 and 7; backlog rows HK-002 to HK-005).

It follows Google's Elephant-Goldfish model (EGM). The "Elephant" is the session that holds the project's context
and drafts; "Goldfish" are fresh reviewers that read the draft and the code with none of that context, each from
one "lens" (design, codebase, readiness, comprehension, structure, scope, invention). The steps so far:
- a brainstorm by seven lenses and a synthesis: `research/phase-3-concepts-brief.md`;
- draft 1, reviewed by seven lenses: 6 Blockers, 29 Majors, 14 Nits (`research/phase-3-plan-review.md`);
- draft 2, reviewed by three lenses: 2 to 3 Blockers left, all in the audit's writes and the catch-up, and 25
  Majors (`research/phase-3-plan-review-2.md`);
- this draft, which answers both reviews and makes two cuts that remove those Blockers' cause rather than guard it:
  the audit applies nothing before the owner's approval (call 3), and the catch-up is not built (call 4).

The owner asked on 2026-11-13 (UTC) for no stop-and-ask in this phase: "deal with things autonomously". Every
question is settled below as Claude's call, with the options rejected and why, and DESIGN section 10 lists them
for the owner to check.

Terms: the **controller** is the session that runs the build and pushes; a **builder** is one agent doing one task;
**the kit** is `claude plugin test`, whose tests drive the hooks with fakes and no model; **the gate** is defined
under "How the build runs".

## Stop rules for the build

- No agent starts a live session, pushes, opens a PR or publishes.
- No change to `version: 1` in the settings, to the agent-guide line, to the "How this file is kept" heading, or to
  `prompts/survey.md` and `prompts/plan.md`.
- A builder that finds an item larger than its entry leaves the larger part undone, files a row, and goes on.
- A question this plan does not settle is the builder's to report, not to decide.
- Tests named below as changed on purpose may change; any other failing pinned test stops the item.

## How the build runs

- Branch `housekeeping/phase-3`, cut from main at b14fdcf (the Phase 2 merge). Five tasks in order, one builder each;
  they share `housekeeping/hooks/register.tsx`, so they never run at once.
- Each item has the named tests below, written to fail before the change. A negative test first shows the positive
  case in the same world, so a hook that fails open cannot pass it by doing nothing.
- The gate, run at the end of each task:
  - `claude plugin test housekeeping`;
  - `node --test housekeeping/node-tests/*.spec.ts` with TEMP and TMP set to a folder in the scratch directory;
  - `claude plugin validate housekeeping`;
  - the name and word searches over the branch's diff and commit messages, against the git-ignored lists in
    `housekeeping/research/raw/`, and the author and committer check (counted, never printed).
- The controller pushes after each task's gate passes (mod-af's root CLAUDE.md, 2026-11-10: "Commit and push each
  piece of work as soon as it is finished, before it is reviewed"). The narrow check runs over the whole branch
  after Task 5; its findings are filed, and the owner decides any fix round (stop rule 3), except a secret, an
  address or a denied file reaching a page or the agent, which the controller fixes at once.
- Engine facts the plan relies on are read from the engine's types and pinned with kit fakes; a kit test proves the
  plugin against the fake, not against the engine. Every such fact is in `research/live-checks.md`.
- Kit fakes to add in `housekeeping/tests/plugin.test.ts`: `git diff --quiet` (exit 0 unless the world says the
  records changed); `git merge-base`, `git diff --name-only`, `git diff -U0` and `git log` with bodies for owed;
  `git log -1` on the records and `rev-list --count <a>..<b>` answered from the world; `git status --porcelain` on
  the records; a stand-in for `prompts/audit.md`; a Bash and a PowerShell tool.call whose result carries
  `gitOperation` and optionally `backgroundTaskId`; `prompt.suggest` and `ui.log` recorders.

### Task 2: `owed`

Files: Create `hooks/core/owed.ts`, `tests/owed.test.ts`; Modify `hooks/core/history.ts`, `hooks/adapter.ts`,
`cli.ts`, `hooks/register.tsx`, `FORMAT.md`, `README.md`, `tests/plugin.test.ts`, `node-tests/cli.spec.ts`.

- **The range.** The base is `git merge-base <main> HEAD`, or a given `--base <ref>` run through merge-base with the
  head; the head is HEAD or `--head <ref>`. The diff is `<base>...<head>`. `--end-of-options` comes before every
  ref. The log reads `<base>..<head>` without `--first-parent` as `%H%x09%s%x00%b`, with trailer lines
  (`Key: value` at the body's end) dropped before matching; only the sha and the subject are printed.
- **The audit's start**, `auditStart(rows, settingsCommit, firstParents)` in `owed.ts`, pure, with its git readers
  in `history.ts`: the duty row whose Trigger holds "/housekeeping audit" (more than one: the first, and a warning
  line); its latest "Last done: YYYY-MM-DD, through <sha>" (FORMAT gains the ", through <sha>" form); the sha
  checked with `git rev-parse --verify --end-of-options <sha>^{commit}` and `git merge-base --is-ancestor`; else the
  commit that added `.housekeeping.json` (`git log --diff-filter=A -1 --format=%H -- :(literal).housekeeping.json`);
  else, and whenever more than 50 first-parent commits follow the start, the oldest 50 after it. It returns the
  range and the last commit read. Tests: a valid duty row sha; a sha not on main; no row and a settings commit;
  neither; more than 50 commits.
- **Reading, with no history walk.** The records at the base, the head and main's tip are read by the existing
  readers (`show`/`filesAt` on each route) with argument builders in `history.ts`; `owed.ts` stays pure over
  `snapshot()` and `idsIn`. Changed paths come first from `git diff --name-only`; then `git diff -U0` in batches of
  paths under about 30,000 characters of command line; binaries are left out. A path or a batch cut short is
  counted as not read, never a stop.
- **The code-name rule** (FORMAT, with test cases): a token in a Trigger is a backticked span, or a word that holds
  `/` or ends in `.` and letters. A row fires when a token matches a changed path as a suffix on a `/` boundary, or
  a whole word on an added or removed line outside the two records and the settings file. Duty rows and slash
  commands are left out. FORMAT's line that backticks mean nothing is amended for Triggers.
- **What it lists**, grouped: rows whose Trigger fired, with the token and the path and line number it matched; rows
  the commits name by ID in the subject or body, with the commit's sha and subject and whether a closing word is
  next to the ID (the words of Task 3); for each listed commit, its changed paths that passed the Read rules, each
  marked where a shell can read it as commands, and the count it excluded; the checklist lines that name those
  rows; rows gone over the range (`historyFrom([snapshot(base), snapshot(head)])`: open at the base, absent at the
  head, in no Done table); rows already settled (moved to Done at the head), apart; IDs the branch adds that main's
  tip or the base already holds. Evidence never includes a line's text, an author or a trailer. The output is
  masked. The mark's text: "(a shell can read this path as commands: put it in no command)".
- **Read rules.** On the plugin route every changed path, both sides of a rename included, is put to the Read rules
  with readTracked's allow rule (an ask with no rule outside the session's folder counts as denied); denied paths
  are excluded with `:(exclude)` pathspecs and counted, never named. The hook keeps in memory, per run, whether the
  Read checks all finished with nothing excluded. README and FORMAT say that `node cli.ts owed` ignores the Read
  rules.
- **Commands.** `/housekeeping owed [--base <ref>] [--head <ref>]`; `node cli.ts owed [--base <ref>] [--head <ref>]
  [--repo <dir>] [--settings <file>]`. Exit 0 with a listing; exit 2 on a usage error, a stop or a git error. With
  nothing between base and head, the reply says to give a base. The time-out reply names the Node owed only when
  the run's Read checks finished with nothing excluded; otherwise it says to run `/housekeeping owed` again.
- Tests: the default and a given base; a denied path counted and its name and lines absent from the reply and the
  time-out reply; a cut-short batch counted as not read; no local main; a shallow clone; each code-name case; a duty
  row not firing; an ID named only in a body; no author or trailer in the output; a marked path; a collision with
  main's tip; a settled row apart; a gone row.

### Task 3: `audit`

- **`prompts/audit.md`**, the procedure, with these rules written out:
  - **Where writing is restricted** (call 11): before anything, look for a rule on who writes the records; if one
    exists, list every case and propose nothing to apply.
  - **Uncommitted edits to the records:** if `git status --porcelain -- <backlog> <playbook>` is not empty, propose
    nothing, list the cases and say why. Never stash, reset, `checkout --` or clean.
  - **An earlier audit branch:** if an unmerged `housekeeping/audit-*` branch exists, stop and name it.
  - **The evidence:** in Claude Code, only the listing handed with this procedure; never run owed over the range in
    this session. Outside Claude Code, `node <home>/cli.ts owed --base <start> --head <main>`. Then, for at most 25
    row-and-commit pairs, strongest first (a closing word next to the ID, then the ID in the subject, then in the
    body), read only the hunks of that commit's allowed paths:
    `git show --format= --end-of-options <sha> -- :(literal)<path> ...`, never a whole commit, never `--stat`. A pair
    with a marked path is a judgement call and goes into no command. Pairs past 25 are counted.
  - **Clear-cut** means all three: a closing word ("close", "closes", "closed", "fix", "fixes", "fixed", "done",
    "land", "lands", "landed", "resolve", "resolves", "resolved", any case) next to the ID in the subject or body;
    the change the hunk shows still present at main's tip (`git show --end-of-options <main>:<path>` holds it); and
    the skeptic agrees.
  - **The skeptic:** a fresh subagent that is not a fork, per batch of 10 cases, given only each row's ID and Item,
    the claim, the sha and subject, and the allowed hunk. Only cases it agrees with are proposed. With no subagent
    available, every case is a judgement call.
  - **Proposing** (call 3): the clear-cut cases as numbered steps, each with its row, its proving sha and subject,
    and what changes; the duty row's update as the last step (or, with no duty row, its addition, word for word:
    `| <next ID> | Audit the records against the commits | none | agent | no: a standing duty | Every 2 weeks:
    /housekeeping audit | — | Last done: YYYY-MM-DD, through <sha> | YYYY-MM-DD |` in the playbook's own column
    order); then the judgement calls (partly done, done differently, gone rows, doors, "opened" work, marked paths),
    listed with their evidence. Approval is the owner's own message, sent after they have seen the numbered steps.
    Nothing else is approval, and nothing is written before it.
  - **Applying, after approval:** a branch `housekeeping/audit-YYYY-MM-DD` from main, made with `git worktree add`
    in a folder under the system temp folder, outside the person's checkout; one commit per step, each naming its
    proving sha; Done rows in the shape of the file's existing Done rows; checklist lines ticked whose rows are all
    closed. Last done moves "through" the last commit read (call 2). The branch is never pushed: it is the owner's.
    The worktree is removed at the end, and before any branch is deleted.
  - **The check after applying:** before and after, `node <home>/cli.ts map --settings <a copy whose mainBranch is
    the audit branch> --out <a file in the system temp folder>`; the settings copy also lives there, outside the
    repository. Expected: closed up by N and open down by N; when the duty row was added, open down by N - 1 and the
    total up by 1. `node <home>/cli.ts owed --base main --head <audit branch>` lists no gone row. Both commands read
    only the records and the audit's own commits, so they are allowed whatever owed excluded. If `map` exits 1
    before applying, apply nothing and list the cases. Any other result: remove the worktree, delete the branch and
    report.
- **`/housekeeping audit`** hands the procedure (`handPrompt`) with owed's listing over `auditStart`'s range and the
