# housekeeping Phases 0 and 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking.

**Goal:**
- **Phase 0:** find out whether the plugin system does what the design needs.
- **Phase 1:** build `housekeeping`'s format, settings, core, `check`, `map`, `init`, short view and
  publishing. The result is a working Route Map for any repository whose files are in the format.

**Architecture:**
- **One pure TypeScript core** (`housekeeping/hooks/core/`) turns the two files' text, a settings object
  and git facts into rows, computed facts, findings, a page and a short text.
- **Two thin callers:**
  - the plugin's hooks module, which reads git through Claude Code and writes through Claude Code's own
    tools;
  - a Node command (`housekeeping/cli.ts`), which reads git with `node:child_process`.
- Neither caller decides anything the core decides.

**Tech stack:**
- TypeScript, run directly by Node 24's type stripping and by the Claude Code plugin engine;
- the Claude Code plugin API (types of build 2.1.309; installed CLI 2.1.314);
- tests: `claude plugin test` with `claude-code/testing` for the core and the plugin, and `node --test`
  for the Node command;
- no npm dependencies.

**Spec:** [`../DESIGN.md`](../DESIGN.md), approved by the owner on 2026-11-03. Read it first: this plan
argues from it and does not repeat it.

**Later plans:** Phases 2 (`survey`, `plan`, dry runs) and 3 (`audit`, `owed`, the automatic parts, the
integration with `loose-ends`, `route` and `decide`) get their own plans once Phase 1 lands, written with
Phase 0's note in hand.

## Global Constraints

- **No repository named in a committed file.** Use the design's descriptions: "the reference repository"
  and "test repository A/B/C". The mapping, paths and commits are in `research/raw/` (git-ignored, local
  only). The names to search for are in `research/raw/names.txt`. Fixtures are made up, never copied
  from any repository (DESIGN §4; stop rule 10).
- **Node:** Node 24 (`v24.13.1` on the build machine). Only type-strippable syntax: no `enum`, no
  `namespace`, no parameter properties. Imports carry the `.ts` extension.
- **The core** (`housekeeping/hooks/core/*.ts`) imports no `node:*` module, and nothing from
  `claude-code` except types. `cli.ts` is never imported by the hooks module.
- **The hooks module** uses static imports of the plugin's own files only, with no `require` and no
  `import()`.
- **The page:**
  - It is one HTML file, pure ASCII, carrying `window.DATA = /*DATA*/null;` exactly once.
  - It reads no clock, no network, no CI and no chat. The same inputs give a byte-identical page.
  - Under 1,000,000 bytes on the reference repository.
- **The short view:** at most 8,000 characters (about 2,000 tokens).
- **Privacy:** never write a page holding a personal email address or a key-shaped string; never show
  commit authors (DESIGN §3.4).
- **Writes from the plugin** go through `$.tool.call({ tool: 'Write', ... })`, reading first as dynamics
  does, so the person's permissions apply. The plugin never commits, pushes or fetches.
- **The partition line** printed by `map`, exactly:
  `<all> rows in all = <closed> closed + <open> open; open = <yes> land now + <choice> small choice + <no> not now; <open backlog> open in the backlog, <open playbook> in the playbook`.
- **Test commands:**
  - core and plugin: `claude plugin test housekeeping`;
  - the Node specs, a gate step beside the other two (the page script's stub-DOM run, Task 8, cannot run in the kit,
    which allows no code from strings): `node --test "housekeeping/node-tests/*.spec.ts"`, which runs
    `page.spec.ts` now and `cli.spec.ts` from Task 11;
  - structure: `claude plugin validate housekeeping`.

  Run them from the repository root.
- **Stop rules** (DESIGN §8) apply to every task. Stop and report before any push, pull request or first
  publish to an artifact.

## Review Focus

1. **Windows text.** A file saved with CRLF line endings, or starting with a UTF-8 byte-order mark, must
   parse exactly like its LF twin. The test is in Task 2.
2. **A missing file or branch.** A playbook missing at main, or a `mainBranch` that does not exist, must
   give an error finding and a plain message, never a crash or an empty page that looks valid. The tests
   are in Tasks 10 and 11.
3. **A hostile cell.** A cell holding `</script>`, `$&`, `$1`, `\|` or non-ASCII text must come through
   word for word, and the page must stay ASCII with one script block. The test is in Task 8.
4. **Loops in the links.** A row that waits on itself, and a two-row cycle, must not hang the unblock,
   chain or lane computations; each is a warning. The tests are in Tasks 3 and 4.
5. **A typo in the settings.** A column name in the settings that matches no header must be an error
   naming the column and the file, not a silently empty map. The test is in Task 5.

## Phase 1: the format, the core, `check`, `map`, `init`, the short view and publishing

**Departures from the design's phase list, decided here:**
- `init` moves into Phase 1, because Phase 1's completion criterion for an empty repository uses it.

### Task 2: reading the files

**Files:**
- Create: `hooks/core/markdown.ts`, `hooks/core/parse.ts`, `tests/fixtures/small.ts`, `tests/parse.test.ts`
- Modify: `FORMAT.md` (the row and section rules)

**Interfaces:**
- Consumes: `Settings`, `Parsed`, `Row`, `DoneEntry`, `ChecklistLine` and `Finding` (Task 1).
- Produces:
  - `normalise(text: string): string`: strips a leading BOM and turns CRLF into LF.
  - `cellsOf(line: string): string[]`.
  - `scanTables(text: string): { section: string; subsection: string; line: number; header: string[]; rows: { line: number; cells: string[] }[] }[]`.
  - `parseFiles(s: Settings, files: Record<FileKey, string | null>): Parsed`.
  - `idsIn(text: string, s: Settings): string[]`.

**Rules to port from the reference generator** (exact; the reference's path is in the local raw notes):
- **Fences.** A line matching `/^\s*(?:```|~~~)/` toggles a fence. Inside a fence nothing is read.
- **Sections.** `## x` sets the section and clears the subsection; `### x` sets the subsection. Any
  heading ends a table.
- **Tables.** A `|` line opens a table when the next line matches
  `/^\|?\s*:?-{3,}:?\s*(?:\|\s*:?-{3,}:?\s*)*\|?\s*$/`. Rows follow until a line that does not start with
  `|`.
- **`cellsOf`.** Trim the line, skip one leading `|`, split on `|` except `\|` (read as `|`), trim each
  cell, and drop a trailing empty cell. Backticks are not special.
- **Short rows** are padded with `''`. A cell count different from the header's is recorded in
  `Parsed.findings` as a `warning` with rule `columns`.
- **Nothing.** A cell is empty-of-meaning when it equals one of `values.nothing`. Multi-value cells
  (Milestone, Waits on) split on `,`, trimmed, empties dropped.
- **Land now:** exactly `yes`, or `/^(small choice|no): (\S.*)$/`. Anything else gives
  `{ state: 'no', why: <raw cell>, valid: false }`.
- **Who:** mapped through `values.who`; anything else is `unknown`.
- **Duplicate IDs:** the first row wins in later lookups; `parseFiles` records rule `id-unique`.
- **Done entries.** Rows of tables inside `##` sections whose title starts with a `done[].sectionPrefix`
  in that entry's file. `ids` are the IDs `idsIn` finds in the `idColumn` cell. An entry's file is
  `done.file`, unless the last of its `ids` starts with a `fileByIdPrefix` value, in which case it is the
  matching file.
- **Checklists.** `- [ ]` or `- [x]` lines under a configured `##` heading; `group` is the `###` heading

### Task 3: computed facts

**Files:** Create `hooks/core/facts.ts` and `tests/facts.test.ts`.

**Interfaces:**

- Produces: `computeFacts(s: Settings, p: Parsed): Facts`.

**Exact rules:**
- **The counts.** `closed` = the number of Done entries, not IDs. `open` = the number of rows. `all` =
  closed + open. `yes`, `choice` and `no` partition the open rows by `landNow.state`. `needYou` = rows
  whose Who is owner or both. `queue` = choice rows plus the needYou rows that are not choice.
  `waitsOnRow` = rows with at least one Waits on ID that is open and not themselves. `noMilestone` = rows
  whose milestones equal `[s.none]`. `perFile` splits each count by file, with Done entries by their file.
- **`unlocks`, `before` and `opens`:** port this algorithm exactly. `known` is the set of open IDs of
  both files.

  ```ts
  for (const r of rows) for (const w of r.waitsOn) if (known.has(w) && w !== r.id) unlocks[w].push(r.id)
  const reach = (start, next) => { const seen = new Set(); const stack = [...next(start)]
    while (stack.length) { const id = stack.pop(); if (seen.has(id) || id === start) continue
      seen.add(id); stack.push(...next(id)) } return seen }
  before[id] = [...reach(id, x => waitsOnKnown(x))]; opens[id] = reach(id, x => unlocks[x]).size
  ```
- **`closedIds`:** every ID in a Done entry's `ids` that is not an open row.
- **`doors`:** rows with `landNow.state === 'no'` whose Waits on is not empty and whose every Waits on
  ID is in `closedIds`.
- **`duties`:** rows whose Trigger starts with `s.duties.triggerPrefix`.
- **`landNow`:** the yes rows that are not duties, sorted by opens (descending), then priority (the
  index in `values.priority`; a missing or unknown value ranks last), then file order.
- **`queue`:** the queue rows, sorted by opens (descending), then the main milestone's position in the
  paths (`milestones[0]`, the first position found across `paths`; unknown last), then priority, then
  file order.
- **`waitingOnRows`:** no-rows with at least one open Waits on ID, in file order.
- **`byHand`:** the other no-rows that are not doors and not duties, in file order.
